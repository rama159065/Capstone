# Notebooks

Five step-by-step notebooks build the financial-report copilot up layer by layer. Notebooks 02–05 import the repo's code (`scripts/...`) instead of copying it; 01 is self-contained. Each runs on **Google Colab** with a few filings, or locally from the repo root. A sixth notebook, `colab_financial_ingest.ipynb`, ingests the full corpus and serves the API + UI.

| # | Notebook | What it tests | Filings | Runtime |
|---|---|---|---|---|
| 01 | [01_chat_templates_pydantic.ipynb](01_chat_templates_pydantic.ipynb) | **Standalone** (no repo clone). All five prompt techniques: zero-shot, few-shot, chain-of-thought, self-consistency and decomposition; LLM-chosen **tool call** (Pydantic `ToolCall`) to **SEC XBRL** as the external source; answers validated as Pydantic `FinancialAnswer`, plus citation and number grounding | none (XBRL API) | CPU |
| 02 | [02_text_rag_chat_templates.ipynb](02_text_rag_chat_templates.ipynb) | Text-only RAG (Qdrant `annual_reports_text`, hybrid + rerank) + templates. Scenarios: filtered, unfiltered, `k=2`, a garbled filing | AMD FY2025, AbbVie FY2025, NVIDIA FY2026, Chevron FY2022 | CPU or GPU |
| 03 | [03_ocr_rag.ipynb](03_ocr_rag.ipynb) | Full-page OCR of garbled statements checked against XBRL; image-region OCR of a chart (2 passes); QA with no OCR, front-first OCR and full OCR | Chevron FY2022 | GPU recommended |
| 04 | [04_visual_rag_colpali.ipynb](04_visual_rag_colpali.ipynb) | Charts and tables as **ColPali image multivectors** in Qdrant (full vectors, exact MaxSim); chart questions, descriptive and exact-number queries; optional vision model | NVIDIA FY2026, Chevron FY2022 | **GPU** |
| 05 | [05_final_qdrant_colpali_rag.ipynb](05_final_qdrant_colpali_rag.ipynb) | Final design: text + OCR + ColPali **mean pooling** (rows/columns) with full-vector rerank. Pooled-only vs prefetch → rerank vs exhaustive; hybrid evidence; **clarifier → LangGraph agent** on the eval set | the four above | **GPU** |

## Ingestion notebooks (Colab, full corpus)

One notebook per vector database. Both download the corpus preset (`min500` or `full`) to Drive, ingest one sector at a time, back the index up to Drive, resume after a disconnect, and can serve FastAPI + Streamlit from the index they built. Run the smoke test first (`SMOKE_TEST = True`).

| Notebook | Index | Page readers | Runtime |
|---|---|---|---|
| [colab_ingest_chroma_db.ipynb](colab_ingest_chroma_db.ipynb) | **Chroma** `annual_reports_vlm` + BM25 file: everything as text, for the text-only Qwen3-8B | per page (`READER = "routed"`): text layer, native tables, OCR, Qwen3-VL; `paidVL` pages: Qwen3-VL checked against OCR, paid model only when it disagrees | GPU (T4+) |
| [colab_ingest_qdrant_db.ipynb](colab_ingest_qdrant_db.ipynb) | **Qdrant** `annual_reports_text` (dense + BM25) and `annual_reports_visual` (ColPali: full vectors on disk, mean-pooled rows/columns in RAM) | text layer, OCR for unreadable pages, ColPali page images (no VLM) | GPU for ColPali; CPU for `STAGES = "text"` |
| [colab_page_audit.ipynb](colab_page_audit.ipynb) | none: a CSV per PDF with the reader each page needs | page analysis only | CPU |

**Serving and testing with LangSmith (Chroma):** in `colab_ingest_chroma_db.ipynb`, run cells 1–3 (restore the index from Drive), then 8–12.
- Cell 8 reads the secrets (`LLM_API_BASE`, `LLM_API_KEY`, `LLM_MODEL`, optional `LLM_CA_CERT`, `LANGSMITH_API_KEY`).
- Cell 9 starts FastAPI + Streamlit on the Chroma index and prints the UI link.
- Cell 10 checks that traces arrive in LangSmith.
- Cell 11 asks one question per route (text, table, comparison, chart, trend, sector trend, report, refusal) and prints the route, the agent path, the Chroma evidence, the LLM answer and a LangSmith link for each.

A question asked in Streamlit is then one trace from `streamlit.conversation` to the LLM calls ([docs/observability_langsmith.md](../docs/observability_langsmith.md)).

**Opening the Colab UI from your PC** (port proxy, Cloudflare tunnel, or local Streamlit against the Colab API): [docs/colab_access.html](../docs/colab_access.html).

**Package versions:** every install in these notebooks uses `pip install -c deploy/colab_constraints.txt` (the versions in `uv.lock`; Colab keeps its torch/CUDA, Jupyter, numpy and pandas). Regenerate it with `python -m scripts.common.colab_constraints` after `uv lock`. The Chroma notebook's cell 8 reports any package whose version differs.

Both ingestion notebooks are generated by [build_ingest_notebooks.py](build_ingest_notebooks.py); edit that file and rerun it instead of editing the `.ipynb`. The older `colab_rag_pipelines.ipynb` (both pipelines behind one `PIPELINE` switch) and `colab_financial_ingest.ipynb` still work.

**Standalone:** [06_chat_templates_pydantic_standalone.ipynb](06_chat_templates_pydantic_standalone.ipynb) doesn't need the repo. Upload that one file to Colab and run it.
- It reads the same four PDFs and prints each file name.
- It asks a Qwen model with zero-shot, few-shot and chain-of-thought templates.
- It validates every reply with Pydantic.
- It uses Qwen3-VL-8B on a Colab GPU by default, or any OpenAI-compatible endpoint.
- Set `SEC_USER_AGENT` in its cell 1.

**Standalone:** [07_langgraph_pdf_to_chroma_text_and_images.ipynb](07_langgraph_pdf_to_chroma_text_and_images.ipynb) also doesn't need the repo, and needs no LLM.
- A LangGraph pipeline reads the same four PDFs with a LangChain loader and splitter.
- It writes two Chroma collections: `financial_text` (MiniLM, 384-d) and `financial_images` (CLIP, 512-d). The PNG files stay on disk.
- Running it again embeds nothing new. Typed questions and images can both search the image collection.
- Measured on CPU: 2,337 chunks and 118 images in about 100 s; database 23 MB, PNG files 55 MB.
- Text search found the gold figure for 2 of 4 test questions. In image search, 5 of 6 test charts were found: first within their PDF for 3, second for 2. The one-word query "chart" missed.
- Most stored images are photos or ruled tables, and CLIP doesn't read numbers. Chroma can't run the ColPali MaxSim search, so this notebook compares with the Qdrant design and doesn't replace it. It hasn't been run on a GPU.

**01 is standalone too:** upload that one file to Colab, set `SEC_CONTACT` in its settings cell, and run all cells. It needs no clone or GitHub token. The steps below apply to notebooks 02–05.

## Running on Colab

1. **Package the code** on your PC, from the repo root: `python -m scripts.common.colab_bundle`. Upload the resulting `output/colab/capstone_code.zip` (about 3.5 MB) to Google Drive as `MyDrive/capstone_rag/capstone_code.zip`. Rebuild and upload it again after you change code. The zip holds `scripts/`, `tests/`, `configs/`, the corpus plans and manifests, and small samples, including uncommitted work. It carries no PDFs, indexes or models.
2. **Open a notebook:** upload the `.ipynb` to Colab (File → Upload notebook), or open it from GitHub.
3. **Choose a runtime:** set it to **GPU** for notebooks 03–05.
4. **Add Colab secrets** (🔑 panel; turn on notebook access):

   | Secret | When needed |
   |---|---|
   | `GITHUB_TOKEN` | only without the code zip: the setup cell then clones the private repo (read-only "Contents" permission is enough) |
   | `SEC_USER_AGENT` | always: `your-name your.email@domain`. SEC requires a contact address |
   | `LLM_API_BASE`, `LLM_API_KEY`, `LLM_MODEL` | for the provided Track B endpoint. Without them, notebooks 01–04 use a small Hugging Face stand-in on the GPU and notebook 05's agent uses the mock |

5. **Run all cells.** Cell 0 mounts Drive and unpacks the code zip to `/content/Capstone`. It unpacks again only when the zip is a new build (`BUNDLE_INFO.json` records the commit and build time). If there is no zip on Drive, it asks you to upload one, and if you cancel it clones the branch. It then installs what that notebook needs and loads the secrets. PDFs are downloaded from EDGAR and SHA-256-checked. `colab_financial_ingest.ipynb` and `colab_rag_pipelines.ipynb` get their code the same way.

**Settings** (set them before the config cell with `os.environ[...] = ...`):

| Variable | Values |
|---|---|
| `NB_LLM` | `auto` (default), `hosted`, `transformers`, `mock` |
| `NB_EMBED` | `local` (MiniLM, the default) or `hashing`; `NB_EMBED_MODEL` sets the model |
| `NB_COLPALI` | `auto` (real on a GPU), `real`, or `fake` (plumbing only) |
| `NB_QUESTIONS`, `NB_MAX_PAGES`, `NB_MAX_VISUAL_PAGES` | smaller runs |
| `NB_OCR_PAGES`, `NB_OCR_LIMIT`, `NB_OCR_SCENARIOS`, `NB_OCR_CUDA=1` | OCR scope; GPU OCR needs `onnxruntime-gpu` |
| `NB_VLM=1` | notebook 04's optional vision-model reading |

**Running locally:** from the repo root use the project venv, which needs a Jupyter kernel installed. The notebooks contain no shell `!` commands, so every cell is plain Python.

## Local verification (CPU)

All five notebooks were executed end to end with:
- the mock LLM;
- MiniLM embeddings from `indexes/models`;
- real OCR;
- the fake ColPali encoder, plus a separate real-ColPali check.

These runs show that the pipeline works. Model-quality numbers need the hosted endpoint. They predate the financial agent's coverage checks (`not_available` and the company check), so answered counts may differ on a rerun.

| Notebook | Measured |
|---|---|
| 01 | The XBRL tool returned exact figures for AMD, Chevron and AbbVie. Pydantic flagged unusable tool calls (`tool_call_error`, with a slot-parser fallback) and the mock's ungrounded values and citations |
| 02 | The right filing was retrieved for **100%** of filtered questions (78% unfiltered). But the gold figure was in the top-5 evidence for only **17%** (11% at `k=2`): question-style queries prefer narrative pages over statement tables, which is why the design puts a facts tool first. Chevron FY2022: 0% |
| 03 | Garbled text: 0 of 6 statement figures. OCR of 12 pages: 5 of 6 at 4.5 s/page. Chart OCR: 4 of 4 values plus the false "12,000". Gold value in evidence: 20% → 40% → 50% (none → front-first 20 → all). Chart values are never indexed at ingest (a gap) |
| 04 | 127 visual pages encoded into a multivector collection; queries and thumbnails work (fake rankings) |
| 05 | Full ingest (4 filings, text + visual). Pooled-only search ~23 ms vs ~220–330 ms with full MaxSim (plumbing timing). Clarifier → agent; 17 of 32 answered with valid citations. The runs found three clarifier bugs (now fixed), an input-guard gap (fixed) and a narrow classifier fallback (documented) |
| Real ColPali (CPU, bfloat16) | Each page gives 1030 vectors = 1024 patches + 6 special tokens; pooled to 38 × 128. NVIDIA p60, Chevron p35 and AMD p65 were ranked first by both full MaxSim and pooled rows. CPU speed is ~73 s/page, so use a GPU |
