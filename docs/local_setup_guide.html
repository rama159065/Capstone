Local setup guide: run the Financial Report Copilot on your own PC

For team members. It sets up the code, the Chroma collection from Google Drive, FastAPI, Streamlit, retrieval (RAG) and the agents that call the hosted LLM.

Tested on 24 November 2026 on Windows 11, in a fresh clone from GitHub with its own copy of the collection (on spare ports, on the main PC): clone, package install, unpacking, counts, model download, FastAPI, Streamlit in a browser, all seven agents and the guardrails. Seven answers compared with the main setup were identical word for word. Not tested: the Drive download from a second person's account, installing Git and uv with winget, a different PC, macOS and Linux.

3. Install the tools and the code

Open PowerShell. Use a short folder such as C:\capstone: some file names are long, and Windows limits full paths to 260 characters.

winget install --id Git.Git -e
winget install --id astral-sh.uv -e

Close PowerShell, open it again, then:

git -c core.longpaths=true clone REPO_URL C:\capstone
cd C:\capstone
git switch master
uv sync --python 3.12

Replace REPO_URL with the address from the owner. uv sync downloads about 530 MB of packages at the exact versions in uv.lock, and Python 3.12 if you don't have it.

Check:

.venv\Scripts\python.exe -c "import chromadb, torch, streamlit, langgraph; print('ok', chromadb.__version__)"

Expect ok 1.5.9. This version must match, because the collection was built with it.

4. Download the collection from Google Drive

Pick one way. Save both files in C:\capstone_downloads.

WayWhenNotes
A. BrowserDefaultOpen the shared link, click Download, then Download anyway (the file is too large for a virus scan)
B. Google Drive for desktopBrowser download stops or restartsThis is how the main PC got it: 6.2 GB copied in about 12 min, checksum correct
C. Six 1 GB partsSlow or unstable connectionAsk the owner to share the folder capstone_rag/chroma_parts

B, with Drive for desktop: in drive.google.com, right-click the shared file → Organise → Add shortcut → My Drive. Then, if Drive is on G:, copy it from wherever the shortcut appears:

New-Item -ItemType Directory -Force C:\capstone_downloads
Copy-Item "G:\My Drive\chroma_db_final.tar" C:\capstone_downloads\

C, join the parts:

cd C:\capstone_downloads
cmd /c "copy /b chroma_db_final.tar.part00+chroma_db_final.tar.part01+chroma_db_final.tar.part02+chroma_db_final.tar.part03+chroma_db_final.tar.part04+chroma_db_final.tar.part05 chroma_db_final.tar"

If the download stays at 0 bytes, see section 10: on the main PC, McAfee blocked Google's download servers.

5. Check, unpack and verify

Checksums must match section 2. If one doesn't, download that file again.

cd C:\capstone
(Get-FileHash C:\capstone_downloads\chroma_db_final.tar -Algorithm SHA256).Hash.ToLower()
(Get-FileHash C:\capstone_downloads\mutual_fund_data.zip -Algorithm SHA256).Hash.ToLower()

Unpack (about 2½ min). Don't run an application on these folders while unpacking.

New-Item -ItemType Directory -Force indexes\rag_home\indexes, indexes\rag_home\secrets, secrets | Out-Null
C:\Windows\System32\tar.exe -xf C:\capstone_downloads\chroma_db_final.tar -C indexes\rag_home\indexes
Expand-Archive C:\capstone_downloads\mutual_fund_data.zip -DestinationPath indexes\rag_home\indexes\mutual_fund

You should now have:

C:\capstone\indexes\rag_home\indexes\
  chroma_db\            chroma\  pages\  vlm_ingest.sqlite3
  mutual_fund\          chroma_mutual_fund\  raw_mutual_fund\  nport_mutual_fund.sqlite3

Verify the collection (a few seconds, read-only):

.venv\Scripts\python.exe -c "import sqlite3; r='file:indexes/rag_home/indexes/chroma_db/'; q=lambda f,s: sqlite3.connect(r+f+'?mode=ro',uri=True).execute(s).fetchone()[0]; print('chunks', q('chroma/chroma.sqlite3','select count(*) from embeddings'), 'bm25', q('chroma/bm25.sqlite3','select count(*) from chunks'), 'filings', q('vlm_ingest.sqlite3','select count(distinct doc_id) from filings'))"

Expect exactly chunks 335699 bm25 335699 filings 509. The app finds chroma_db by itself; no path setting is needed. After section 8 works, you can delete C:\capstone_downloads (6.2 GB).

6. Models, key and certificate

Models (about 220 MB, once). They run on your CPU:

$env:HF_HUB_DISABLE_SYMLINKS_WARNING = "1"
.venv\Scripts\python.exe -W ignore -c "from huggingface_hub import snapshot_download as d; d('BAAI/bge-small-en-v1.5', max_workers=1, allow_patterns=['*.json','*.txt','*.safetensors','1_Pooling/*']); d('cross-encoder/ms-marco-MiniLM-L-6-v2', max_workers=1, local_dir='indexes/rag_home/models/ms-marco-MiniLM-L-6-v2', allow_patterns=['*.json','*.txt','model.safetensors']); print('models ready')"

Keep max_workers=1: without it, the download failed on a Windows PC without Developer Mode (WinError 1314).

Certificate and key from the owner:

Copy-Item "$HOME\Downloads\llm_ca.crt" indexes\rag_home\secrets\llm_ca.crt
notepad secrets\llm_api_key.txt      # paste the key, one line, save and close
git status --short                   # must not list anything from secrets or indexes

Both folders are ignored by git. Never commit, share or post the key.

7. Start FastAPI and Streamlit

Use two PowerShell windows and keep both open.

Window 1: FastAPI

cd C:\capstone
$env:LLM_API_KEY = (Get-Content secrets\llm_api_key.txt -Raw).Trim()
$env:LLM_API_BASE = "https://103.42.50.41:1032/v1"
$env:LLM_MODEL = "Qwen/Qwen3-8B"
$env:LLM_MAX_TOKENS = "1024"
$env:DEFAULT_LLM_PROVIDER = "hosted"
$env:HF_HUB_OFFLINE = "1"
$env:LANGSMITH_TRACING = "false"
$env:RAG_REQUEST_TIMEOUT_SECONDS = "180"
$env:RAG_HTTP_TIMEOUT_SECONDS = "90"
$env:OMP_NUM_THREADS = "4"
.venv\Scripts\python.exe -m uvicorn scripts.api.api_app:app --host 127.0.0.1 --port 8000

Wait for Application startup complete, then wait 1–2 minutes while the index warms up. A question asked during the warm-up can fail once with not_grounded; ask it again.

Window 2: Streamlit

cd C:\capstone
$env:API_BASE_URL = "http://127.0.0.1:8000"
$env:DEFAULT_LLM_PROVIDER = "hosted"
.venv\Scripts\python.exe -m streamlit run scripts\ui\api_streamlit_app.py --server.port 8501 --server.address 127.0.0.1

Open http://127.0.0.1:8501. FastAPI's own page is http://127.0.0.1:8000/docs.

Health check (third window):

Invoke-RestMethod http://127.0.0.1:8000/health | ConvertTo-Json -Depth 5
FieldExpect
runtime.financial_backendfinancial_vlm
runtime.vlm_index_readytrue
runtime.reranker, runtime.ca_certtrue

langsmith.api_key_setfalse (tracing is off)

runtime.index_ready is false here; that is the Qdrant index, which isn't used.

Stop: press Ctrl+C in both windows.

9. Rules for the team

  • One question at a time across the team. The hosted LLM allows one active request per key. If two people ask together, one waits or gets HTTP 429. Agree on slots, especially during the demo.
  • Without using the LLM, you can check retrieval with /retrieve, or set $env:DEFAULT_LLM_PROVIDER = "mock" before starting FastAPI. Mock answers aren't real answers.
  • Run only one FastAPI on a collection. Chroma isn't safe with two processes on one folder.
  • Don't run ingestion commands on chroma_db. Work on a copy if you need to change it.
  • LangSmith is off. Turn it on only when agreed, because the free plan has 5,000 traces a month.
  • To update the code later: git pull, then uv sync --python 3.12, then restart both windows. The collection stays.

11. macOS and Linux (not tested)

The same steps, with these differences: install uv from https://docs.astral.sh/uv; use .venv/bin/python instead of .venv\Scripts\python.exe; export NAME=value instead of $env:NAME = "value"; shasum -a 256 for checksums; tar -xf and unzip. Chroma's files were built on Linux and work on Windows, so they should work there too.
