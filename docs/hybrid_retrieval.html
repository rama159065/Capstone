Hybrid Chroma and Qdrant retrieval

The Financial Report Copilot has two indexes built from the same annual reports. Chroma (pipeline 1) holds what OCR and vision models read on each page, values included. Qdrant (pipeline 2) holds ColPali vectors that find a page from its pixels. Each one alone misses some chart and table questions; the hybrid backend (RAG_BACKEND=financial_hybrid) uses Qdrant to find the page and Chroma to read it. This page explains the design, the code changes, how to run it locally, and the questions that test it on one filing (Chevron 2022).

Chevron 2022 shows it plainly. Every page of that PDF has a font-encoded (garbled) text layer. Page 35 holds the production and reserves charts: net crude oil 1,440 kbd, natural gas 7,677 MMcfd, NGLs 279 kbd, proved reserves 11.2 billion BOE. Pipeline 2 stored page 35's garbled text, and none of those four values is anywhere in the Qdrant text, so Qdrant alone can only point at the page. Pipeline 1's Qwen3-VL reading of page 35 has the values; ColPali makes sure that page is retrieved.

Retrieval steps (scripts/rag/financial_hybrid.py)

  1. Chroma search (financial_ingest_chroma_db.retrieve_for_agent): dense bge-small and BM25 FTS5 over the reading chunks, fused by RRF (k = 60), filtered by ticker, fiscal year and sector.
  2. Same-page expansion (with_page_values): a retrieved page_description chunk without any other chunk of its page brings up to 3 of that page's reading chunks, ranked with it (retrieval_paths: vlm_text, same_page).
  3. Visual search, when the plan includes visual_search. RAG_FIN_VISUAL is auto by default for the hybrid (the planner, or chart and figure words in the question, decide), 1 for every question, 0 to turn it off. ColPali embeds the question; Qdrant prefetches 200 pages by the mean-pooled row and column vectors and the text summary vector, then ranks them by exact MaxSim over the full on-disk multivectors. The best 3 distinct pages are kept.
  4. Page reading (page_evidence): for each ColPali page, Chroma's chunks of that page (values first, description last). A page Chroma never read falls back to pipeline 2's own text of the page.
  5. Fusion (fuse): reciprocal rank over Chroma's list and ColPali's pages. ColPali adds pages but does not displace text hits: a chunk found both ways adds both scores and moves up; a chunk only ColPali found ranks after Chroma's top k. Every hit keeps the shared evidence format, so citations, the critic and the API need no change.

Critic: figures only a VLM read

Each Chroma chunk carries unverified_numbers: figures the page reader wrote that neither the page's text layer nor OCR prints. financial_tools.numeric_grounding now returns unverified: answer figures that appear in a cited chunk only as such a figure. They still count as grounded (the reading states them), but governance adds the trigger unverified_vlm_figure, so the answer is shown with final_status: pending_human_review instead of being auto-approved. A figure stated without the flag by any other cited chunk (another page, or pipeline 2's text of the same page) counts as confirmed.

5.3 What each column should show

  • Chroma only (financial_vlm): H1–H4 are answered when Qwen3-VL read page 35 correctly and its chunk ranks in the top k. The description chunk now brings the values with it.
  • Qdrant only (financial_qdrant, RAG_FIN_VISUAL=1): H1–H4 find page 35 but its text has no values, so the expected status is insufficient_evidence or evidence_only. H5–H9 come from OCR text.
  • Hybrid: H1–H4 cite a page 35 chunk with retrieval_paths including visual and the values in the text; H5–H9 as Chroma or better. If a figure appears only in Qwen3-VL's reading and nowhere in the OCR text, the status is pending_human_review with trigger unverified_vlm_figure: that is the critic working, not a failure.

6.3 What this shows

  • Qdrant alone fails every chart question on this filing: ColPali can point at chart pages, but the text it hands the agent is the garbled text layer, so no value reaches the answer. H6 also misses, because the revenue row is in OCR text the MiniLM search ranked lower.
  • Chroma alone succeeds here because this test index holds one filing (357 chunks), filtered to CVX 2022, so the search space is small. The failure cases from section 1 (a values chunk outranked across many filings, rows past 512 tokens) show up at corpus scale, not on one PDF.
  • CPU ColPali was weak on these questions: it ranked other chart pages (25, 8, 33, 13) above page 35 for three of the four chart questions and found page 35 only for H3. With equal fusion weights those pages pushed Chroma's correct chunks from rank 2–5 down to 8–10; the fusion now lets ColPali add pages without displacing text hits, and the hybrid keeps Chroma's ranks on every question.
  • Net result: the hybrid is never worse than Chroma alone, and adds ColPali's pages as extra evidence when the text search misses a page. Its benefit has to be measured on the full corpus, where text search is harder.

7. Limits

  • ColPali on CPU is slow to load (about 6 GB) and adds a few seconds per chart question. On a GPU machine it runs in float16 automatically.
  • Local Qwen3-VL-2B reads charts less reliably than the Gemini readings in the final Colab index. Wrong readings are exactly what the unverified_vlm_figure review catches; the full demo should use the Gemini index.
  • Embedded Qdrant is single-process; a Qdrant server (QDRANT_URL) lifts that.
  • Same filing in both indexes: the hybrid joins them by doc_id and page, so both must be built from the same manifests.
