End-to-end walkthrough: Streamlit, FastAPI, the agents, the checks, Chroma and the hosted LLM

This guide follows real questions through the whole Financial Report Copilot, one for each agent. Each question starts in the Streamlit chat and goes through FastAPI, the clarifier, the agent's LangGraph steps, the guardrails and the critic, retrieval from the Chroma index, and the hosted LLM's answer. Every result below comes from a run on 21 November 2026. Five of the runs were traced in LangSmith as evidence (section 9).

Related pages: agent_flows.md (every node and routing rule), agents_flows.md (what each agent decides), fastapi_api.md (routes), annual_report_rag_structure.md (the index), observability_langsmith.md (tracing) and agent_test_questions.html (more test questions).

2. Starting it

In PowerShell, from the repo root. The keys stay in the gitignored secrets\ folder:

$env:LLM_API_KEY  = (Get-Content secrets\llm_api_key.txt -Raw).Trim()
$env:LLM_API_BASE = "https://103.42.50.41:1032/v1"
$env:LLM_MODEL    = "Qwen/Qwen3-8B"
$env:LLM_MAX_TOKENS = "1024"            # the server stops replies at 512 tokens unless asked for more (max 1024)
$env:DEFAULT_LLM_PROVIDER = "hosted"
$env:RAG_BACKEND  = "financial_vlm"
$env:RAG_VLM_DIR  = "$PWD\indexes\rag_home\indexes\chroma_db_bge"
# optional, only when traces are wanted (free plan: trace single questions, never batch runs)
$env:LANGSMITH_API_KEY = (Get-Content secrets\langsmith_api_key.txt -Raw).Trim()
$env:LANGSMITH_PROJECT = "annual-report-copilot"
uvicorn scripts.api.api_app:app --host 127.0.0.1 --port 8000

The LLM's CA certificate is found automatically at indexes\rag_home\secrets\llm_ca.crt. In a second window:

streamlit run scripts\ui\api_streamlit_app.py      # http://localhost:8501

GET /health should show financial_backend: financial_vlm, vlm_index_ready: true, ca_cert: true and, when the LangSmith key is set, langsmith.api_key_set: true with tracing_all_requests: false.

Choosing an agent (Technique)

What an answer shows: a status badge (answered, evidence_only, pending_human_review, not_available, refused), the answer with [chunk_id] citations (the ID names the filing and page, for example annual_report_edgar_ars_JPM_2025_p0198_vlm0 is JPM's FY2025 report, page 198), an Agent run panel (the steps taken, the router's decision, the plan, every tool call and calculation), Citations and Human Review (citation check, support check, review triggers) and Evidence (the retrieved chunks). If the clarifier needs something, it asks with buttons (a company list, years, Yes/No).

6. Retrieval from Chroma

Every text_search is one filtered search for one company and fiscal year:

  1. Filter: Chroma where on ticker, year (and sector when set), so a JPM 2025 search can only return JPM's FY2025 annual report.
  2. Dense: the question embedded with bge-small (the model the index was built with), 50 nearest chunks by cosine.
  3. BM25: the same filter over the FTS5 sidecar (chroma/bm25.sqlite3).
  4. Fusion: reciprocal rank fusion (k = 60), keeping the top k (3 per target for comparisons and trends, 5 for a single lookup).
  5. Chart pages: when a chart's page_description chunk is found without its values, up to 3 reading chunks of the same page follow it.
  6. Searches for different targets run in parallel (4 workers); results keep target order. A target with no usable evidence gets one broadened retry if the step budget allows.

Chunks come from the routed page readers (text layer, native tables, OCR, Qwen3-VL, paid model). Each one carries reader, page, doc_id and, for vision readings, unverified_numbers, so the critic can tell which figures only a vision model saw.

7. The runs, agent by agent

7.1 Router (supervisor)

Question: "What was Citi's U.S. Personal Banking net income in 2025 compared with 2024?" (technique router) LangSmith trace

Step What happened
Clarifier Company C, years 2024–2025, measure net income → ready
route_step Hosted LLM proposed trend; the rule parser agreed (decided_by: llm) → trend agent
trend_fetch_step Coverage, then one search for C 2024 and one for C 2025 (3 chunks each)
trend_series_step The LLM copied each year's figure; code kept each only because that year's chunk states it; change and % change computed in code
answer_step → critic_step Answer written; 4 figures grounded, judge supported
Result answered, 25 s, 8 of 10 steps

Citi's U.S. Personal Banking net income in 2025 was $14,306 millions of dollars, compared with $12,682 millions of dollars in 2024, an increase of +1,624.00 or +12.81% [annual_report_edgar_ars_C_2024_p0322_vlm1, annual_report_edgar_ars_C_2025_p0024_vlm0].

Verdict: wrong. Those are Citi's total net income figures. The segment's are $3,097 million (2025) and $1,382 million (2024). The trend agent keeps the measure ("net income") but not the segment, and both checks passed because both figures really are in the cited chunks. This is the main remaining failure type (section 8).

The first run of this question (before fix 1) went to the sector agent instead, because "Citi" wasn't a known name and "Personal Banking" read as the banking sector. The critic caught it: it saw Bank of America's figures cited for Citi, withheld the answer and sent it for review (trace).

7.2 Q&A agent (agentic_graph)

Comparison: "Which company had higher net income attributable to the company in its fiscal year ending in 2025: JPMorgan Chase or Bank of America?" LangSmith trace

Step What happened
plan_step Hosted LLM: tools coverage_lookup, text_search, calculator; rules split the comparison into JPM 2025 and BAC 2025
retrieve_step Two filtered searches in parallel, 3 chunks each
evidence_guard_step Nothing flagged
answer_step → critic_step 2 figures grounded, judge supported, citations valid
Result answered, 20 s, 8 of 10 steps

JPMorgan Chase had a net income of $48,665 million, while Bank of America had a net income of $30,509 million. Therefore, JPMorgan Chase had higher net income attributable to the company in its fiscal year ending in 2025. [annual_report_edgar_ars_JPM_2025_p0346_vlm4, annual_report_edgar_ars_BAC_2025_p0073_vlm0]

Verdict: right conclusion, wrong JPM figure. Bank of America's $30,509 million is correct. JPM's FY2025 figure is $57,048 million (the trend run below finds it). The $48,665 million comes from a pro forma note in JPM's 2025 10-K, showing 2023 net income as if the First Republic acquisition had happened earlier. Same failure type as 7.1.

Text: "Who was Bank of America's independent auditor for fiscal year 2025?" → answered in 17 s, but the answer says the evidence doesn't name the firm. The search found the "Report of Independent Registered Public Accounting Firm" page, but not the chunk with PricewaterhouseCoopers' signature. A safe miss (no guess), not a correct answer.

Chart: "According to the production charts in Chevron's 2022 annual report, what was Chevron's net crude oil production in 2022?" → evidence_only in 24 s, 10 of 10 steps. The search returned results-of-operations tables, not the production chart page (1,440 thousand barrels per day). The model said the figure wasn't stated, the judge found the answer only partly supported, the repair didn't help, and the answer was replaced by cited excerpts and sent for human review. A retrieval miss, handled safely.

7.3 Trend agent (trend_graph)

Question: "How did JPMorgan Chase's net income trend from 2022 to 2025?" LangSmith trace

Step What happened
route_step Technique fixed to the trend agent
trend_fetch_step 4 searches (JPM 2022, 2023, 2024, 2025), one per filing
trend_series_step One figure per year, each kept only if that year's chunk states it; 3 changes, 3 % changes and the CAGR computed in code
answer_step → critic_step 11 figures grounded, judge supported
Result answered, 42 s, 8 of 10 steps

JPMorgan Chase's net income increased from 37,676 millions of USD in FY2022 to 49,552 in FY2023 (+31.52%), rose to 58,471 in FY2024 (+18.00%) and decreased to 57,048 in FY2025 (−2.43%). The CAGR from FY2022 to FY2025 was 14.83%. (each year cites its own filing: JPM 2022 p.180, 2023 p.205, 2024 p.207, 2025 p.198)

Verdict: correct. All four figures match JPM's consolidated statements; the arithmetic was done in code.

7.4 Sector trend agent (sector_trend_graph)

Question: "How did banking sector net income trend from 2022 to 2025?" LangSmith trace

Step What happened
Coverage 11 banks in the index; MTB left out (no FY2022–2024 filings), USB and WFC over the 8-company limit
sector_fetch_step 32 searches (8 banks × 4 years)
sector_series_step Each figure read from the statement row in code first; the LLM only where no row matched, and its figure kept only on a line naming the measure. Panel = banks verified in every year
answer_step → critic_step 24 figures grounded in code; the support judge's reply was cut off (below)
Result evidence_only, 117 s, 10 of 10 steps; human review (unsupported_claims, low_sector_coverage)

The panel the code built (USD millions):

Bank FY2022 FY2023 FY2024 FY2025
Bank of America 27,528 26,515 27,132 30,509
Fifth Third 2,446 2,349 2,314 2,522
JPMorgan Chase 37,676 49,552 58,471 57,048
Panel total 67,650 78,416 (+15.9%) 87,917 (+12.1%) 90,079 (+2.5%)

Five banks were dropped because a year's figure couldn't be verified (BNY, C, COF, STT, TFC), so the panel is three banks and the answer is flagged low_sector_coverage. The figures shown are correct.

Why evidence_only: the LLM support judge lists each claim as JSON. For 24 figures, its reply ran past the 1,024-token output limit and was cut off, so no verdict could be parsed and the answer was withheld (fail closed). The table above is in the result (sector_trend) and on screen in Streamlit's "Sector trend" panel (expanded by default); only the generated prose was withheld.

Bugs found by running with the hosted LLM, and fixed (the mock LLM in the tests never showed them; a test now covers each):

# Bug Effect Fix
1 "Citi" wasn't a company alias; "U.S. Personal Banking" read as the banking sector One-company question sent to the sector agent common/companies.py: "citi" added; test in test_financial_clarifier.py
2 Qwen3-8B marked ordinary questions is_plain_text: false Comparison, chart and trend questions refused in 2 s llm_plain_text_classifier: the rule guard decides plain text; the LLM's view kept as llm_is_plain_text; prompt states what "plain text" means
3 The plain-text step replaced the question with the LLM's safe_query (Qwen3-8B returned true) The agent answered the question "True" The classifier never rewrites the question (fixed 20 Nov)
4 Sector answer prompt over the model's 8,192-token context HTTP 400, request failed after ~70 s Sector evidence excerpts capped at 4,000 characters (SECTOR_CONTEXT_CHARS); the table already carries every figure and chunk ID
5 Support judge's JSON longer than the output limit on long answers 11-row fund answer withheld Judge asked for short claims, a reason only for unsupported ones; a cut-off reply is reported as such

Configuration found: the course server stops a reply at 512 tokens unless the request sets max_tokens (maximum 1024). Set LLM_MAX_TOKENS=1024 everywhere (.env.example already does; the Colab notebooks don't yet).

Open limits

  • Right filing, wrong row (7.1, 7.2): the agent cites a real figure from the right filing, but for a different concept or year (company total for a segment, a pro forma note for the actual). Number grounding can't catch this, and Qwen3-8B as judge passed both. This matches the Week 1 analysis, where it was the largest failure type with RAG (week1_failure_scenarios.md).
  • Long answers and the judge: with 24 figures the judge's JSON still doesn't fit in 1,024 tokens, so sector answers end as evidence_only (safe, but no prose). Judging in batches would fix it.
  • Retrieval misses (auditor name, Chevron chart): the answers were safe, not wrong; a larger top_k or the ColPali visual search would help.

10. Reproducing

# API and Streamlit as in section 2, then:
python -m scripts.evaluation.streamlit_walkthrough                 # all 11 questions, nothing traced
python -m scripts.evaluation.streamlit_walkthrough --trace         # + one LangSmith trace per agent (5 traces)
python -m scripts.evaluation.streamlit_walkthrough trend fund      # selected cases

The script sends each question through Streamlit's own build_payload and post_json and writes output/walkthrough/<case>.json (the full response, including agent_run) and summary.json. A full run takes about 5 minutes on this PC and makes about 50 hosted-LLM calls (the sector trend alone makes 19). In the Streamlit chat, the same questions take the same paths; the wording, and sometimes a figure the LLM picks, can differ between runs because the hosted model's replies aren't fully repeatable.
