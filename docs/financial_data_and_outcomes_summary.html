Annual reports: what data they contain, and what this project delivers

Date: 2026-11-04. This is a short overview for the capstone team and reviewers. Figures marked measured were measured on the project corpus; target marks an acceptance goal, not a result. Details are in financial_rag_final_design.md.

1. The documents

DocumentFormatWhat it isRole in this project
Annual report to shareholders (Form ARS)PDF, on SEC EDGAR since 2023The "glossy" report: CEO letter, highlights, charts and photos, usually followed by the full 10-KMain corpus: page images, charts, narrative
Form 10-KHTML with inline XBRL tagsThe official annual filing; every financial figure is machine-taggedClean text and exact numbers
Proxy statement (DEF 14A)HTML with XBRL (ecd taxonomy)Governance, executive pay, pay-versus-performance and shareholder returnExact figures for performance charts
SEC companyfacts APIJSONAll tagged figures per company across yearsGround truth and cross-checks
AnnualReports.com PDFsPDF (third-party mirror)Older years and companies without an ARS on EDGAR (e.g. Apple)Apple, and the existing report profile

Corpus downloaded (measured): 100 official ARS PDFs from 27 companies, fiscal years 2022–2026. That is 14,701 pages (147 per document on average, 76–562), 0.98 GB. 30 AnnualReports.com PDFs are kept for Apple and three others.

What this means: the PDF is best for seeing the report (layout, charts, photos), and the 10-K HTML/XBRL is best for reading exact numbers. The project uses both.

3. How each kind of data is captured

Data typeHow it is capturedWhere it is stored
Financial figuresXBRL facts from the 10-K (and proxy)Facts database: exact values with period, unit and source
Narrative text10-K sections; ARS front pages (OCR where the text layer is garbled)Qdrant docs_text: dense + number-aware keyword search
Tables10-K HTML tables with row/column headers and unitsQdrant docs_text + facts database
Charts and infographicsColPali page embeddings (full vectors + row/column pooled)Qdrant visual_pages
Numbers printed in chartsPDF text labels; validated OCR; reviewer approval (tiers T1–T6)Facts database (chart_value)
Photos and diagramsColPali embeddings; page rendered on demandQdrant visual_pages + PDF
ProvenanceAccession number, URL, SHA-256, page, bounding boxManifest + payload of every record

4. What the project delivers

4.1 Capabilities

OutcomeWhat the user gets
Financial Q&A (chat)Questions in plain English, e.g. "What was Chevron's net income in FY2025?", "Why did Nvidia's data-center revenue grow?", "Show the shareholder-return chart". Answers cite the filing, page and source, and follow-up questions keep their context
Complete company report (job)"Generate a complete financial report for Apple" produces a PDF/Markdown report with financial statements, ratios, trends, charts, segment analysis, risks and commentary. Every number traces to a filing figure, with 17 arithmetic reconciliations in the existing pipeline
Honest handling of missing dataThe report says "not disclosed (searched: …)", or shows a derived value with its formula, or uses a figure from another year's filing, clearly labelled. It never guesses
Multimodal searchFinds pages by meaning, keywords, exact figures, or how a chart looks
Human-in-the-loopApproval steps before publishing a report; a review screen for uncertain chart readings; checks for financial-advice language and citations
Resumable, auditable runsCheckpoints after every step: resume after a failure, rerun one section, keep versioned outputs, full trace
InterfacesFastAPI backend + Streamlit UI; demo on a Colab runtime or an always-on VM

5. Limits

  • The LLM is the provided hosted ≤8B model (Track B rule). Report prose is kept short and structured, and all numbers are filled in by code.
  • Values that no document prints (for example unlabelled chart segments) are described only as trends; they are never estimated.
  • ARS PDFs on EDGAR start in 2023, and some companies (e.g. Apple) file none. Older years come from 10-K HTML or the AnnualReports.com mirror.
  • Colab is used for ingest and demos. An always-on service needs a VM.
  • Estimates in the design (T4 encoding speed, end-to-end latency) are confirmed only once the Colab evaluation runs.
