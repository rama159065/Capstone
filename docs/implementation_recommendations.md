## 1. Decisions this plan assumes

| Area | Recommendation |
|---|---|
| Domain implemented | `financial_report_qa` only; the other five domains keep the current code |
| Corpus | **100 official SEC EDGAR annual-report PDFs (Form ARS)**, already downloaded: 27 companies, FY2022–FY2026, 14,701 pages, 0.98 GB (**measured**) |
| Apple | Keep the AnnualReports.com PDFs for Apple. Apple files no ARS, and `apple_2024.json` pins that PDF's SHA-256 |
| Vector database | Qdrant **server** on the Colab VM (`RAG_BACKEND=qdrant`, `QDRANT_URL`), not embedded local mode |
| Text index | `docs_text` as today: dense + IDF-sparse ("bm25"), every page, OCR text included |
| Visual index | `visual_pages`: full ColPali vectors **on disk, float16, no HNSW** + **mean-pooled rows and columns (38 vectors each) in RAM with HNSW** + the text `summary` vector |
| Retrieval | Three prefetches (rows, columns, text) → rerank with the full ColPali vectors → top 20 → fuse with `docs_text` → **top 5 pages to the LLM** |
| Pooling method | **Mean** (Qdrant: NDCG@20 0.952 vs 0.759 for max, **published**). Max pooling is not used |
| Numbers in answers and reports | Always from deterministic extraction (`analysis.json`) or quoted evidence, never generated by the LLM |
| Agents | Flow A (report job, 15 top-level nodes + a 6-node section subgraph) and Flow B (Q&A, 10 nodes), with persistent LangGraph checkpoints |

| 10-K HTML (Inline XBRL) | Optional later, for years before 2023 or companies without ARS | none yet | Not used; render to PDF with PyMuPDF if needed (tested: Apple FY2024, 154 pages in 0.5 s) |

### 2.2 Recommendations

1. **Add `data/raw/financial_report_qa/edgar/pdfs/` to `.gitignore`**, but commit `edgar/pdf_manifest.jsonl`. The PDFs are 0.98 GB, and the manifest holds the URL, accession number and SHA-256 for each one, so the PDFs can be downloaded again.
2. **Treat the manifest as the source of record.** Ingest from the manifest, not from a folder glob, so `ticker`, `year`, `source_url`, `accession_number` and `content_sha256` reach the Qdrant payload.
3. **Keep the download options as they are:** `--max-mb 80` and `--min-pages 20`.
   - Raise the limit to 120 MB only if WMT FY2024 (115 MB) is needed.
   - AAPL, XOM, UNH, ORCL and LLY file no ARS, and META's ARS filings contain no PDF. Use AnnualReports.com or rendered 10-K HTML for those companies.
4. **Use XBRL facts as a numeric cross-check**, not as the main source.
   - The `numeric_consistency_critic` compares report figures with companyfacts values for the same concept and period.
   - Any mismatch above rounding sends the report to `needs_review`.
5. **Record each source's licence or terms** in the manifest's `source_name`. EDGAR is the official record; AnnualReports.com is a third-party mirror.

## 3. Ingestion

### 3.1 Pipeline per PDF (one pass on the Colab GPU)

```text
manifest row → SHA-256 check → for each page:
   text (PyMuPDF) + tables (find_tables → table_markdown) + selective OCR (RapidOCR)
   → docs_text points (dense + sparse, payload)
   if visual page: render PNG at 1.5× → ColPali (GPU) → 1030 × 128
      → mean rows (38) + mean cols (38) → visual_pages point (4 named vectors + payload)
→ metadata.sqlite3 records the document → snapshot every N documents
```

### 3.2 Recommendations

| # | Change | Why | Where |
|---|---|---|---|
| 3.1 | **Manifest-driven ingest**: pass `ticker`, `year`, `company`, `source_url`, `accession_number`, `content_sha256` as metadata | `ingest()` keeps only `ticker`/`year` today, and citations need the public URL | `multimodal_rag.LocalRAG.ingest`, new loop over `pdf_manifest.jsonl` |
| 3.2 | **Raise the visual-page threshold** from `drawings > 4` to about `> 40` | The current rule marks **59%** of pages as visual; `> 40` marks ~**40%** (**measured**, 3,236 pages). Each visual page costs GPU time, 258 KB of vectors and 376 KB of PNG | `multimodal_rag.py:329` |
| 3.3 | **Try the text table strategy as a fallback**: `find_tables(strategy="text")` when none are found | Tables without ruled lines (MSFT-style) give 0 tables with the default strategy (**measured**); `strategy="text"` is untested | `multimodal_rag.py:323` |
| 3.4 | **Run OCR and ColPali in the same pass** | The batch approach deletes PDFs and PNGs after each batch, so a later backfill has nothing to read | Ingest loop |
| 3.5 | **Encode on GPU in bfloat16 on L4/A100, float16 on T4**, batch 4–16. Stop on non-finite output | The repo default (`4bit` on CPU) is for the local profile. CPU took 43 s/page in float32 (**measured**); Qdrant reached 1.81 pages/s on an A100 including upload (**published**) | `colpali_retrieval.load_colpali`, env `RAG_COLPALI_DEVICE=cuda`, `RAG_COLPALI_QUANTIZATION=none` |
| 3.6 | **Compute pooled vectors at ingest** from the first 1,024 patch vectors, reshaped to 32 × 32. Keep the 6 special tokens. | Patches come first, then the 6 tokens (**measured**); same as Qdrant's code | `colpali_retrieval.ColPaliEncoder` |
| 3.7 | **Add pooling settings and datatype to the ColPali signature** | The existing guard then refuses a mismatched index instead of mixing schemas | `ColPaliEncoder.signature` |
| 3.8 | **Store PNGs under a fixed root** (`/content/rag/pages/<doc_id>/page_NNNN.png`) | `image_path` is stored as an absolute path (`multimodal_rag.py:369`) | Ingest |
| 3.9 | **Backfill pooled vectors without the GPU** for an existing index | Pooled vectors can be computed from the stored full vectors | `backfill_visual` |

## 4. Qdrant schema and retrieval

### 4.1 Collections

| Collection / vector | Shape | Index | Storage | Datatype | Purpose |
|---|---|---|---|---|---|
| `docs_text.dense` | 384 (all-MiniLM-L6-v2) | HNSW | on disk (as today) | float32 | Text recall |
| `docs_text.bm25` | sparse IDF | sparse index | as today | — | Keyword recall |
| `visual_pages.colpali` | 1030 × 128, MaxSim | **`m=0` (none)** | **on disk (mmap)** | **float16** | Rerank only |
| `visual_pages.mean_rows` | 38 × 128, MaxSim | HNSW | **RAM** | float16 | Visual first stage |
| `visual_pages.mean_cols` | 38 × 128, MaxSim | HNSW | **RAM** | float16 | Visual first stage (column structure in tables) |
| `visual_pages.summary` | 384 | HNSW | RAM | float32 | Text first stage for visual pages |

Payload: `domain`, `doc_id`, `ticker`, `year`, `company`, `page`, `content_type`, `text`, `table_markdown`, `image_path`, `source_url`, `accession_number`, `ocr_artifact_uri`, `colpali_model`, `pooling`. Use `on_disk_payload=True`. Add payload indexes on `domain`, `ticker` and `year` for filtered queries.

Changing the schema requires **a new `RAG_LOCAL_DIR` and a fresh ingest**. The existing signature checks enforce this.

### 4.2 Query flow (one `query_points` call for the visual side)

```text
query → ColPali query vectors (pads removed) + MiniLM text vector
      → prefetch mean_rows (limit 100) ┐
      → prefetch mean_cols (limit 100) ├─► rerank with full colpali MaxSim → top 20 visual pages
      → prefetch summary   (limit 100) ┘
docs_text: dense + bm25 → RRF (k=60) → lexical rerank (as today)
fuse visual + text hits → evidence_guard → top 5 pages → answer_agent
```

| # | Recommendation |
|---|---|
| 4.1 | Replace the single text prefetch in `retrieve_visual` (`limit=max(30, top_k)`) with the three prefetches. Today, ColPali only reranks pages the text search already found. |
| 4.2 | Start with **limit 100 per prefetch** (≤300 unique candidates). Use 200 only if the Colab evaluation shows higher recall. Qdrant used 200 per shard with 4 shards (**published**). |
| 4.3 | Always `with_vectors=False`. Vectors stay inside Qdrant, and the application handles only IDs, scores and payload. |
| 4.4 | Apply `ticker`/`year` filters inside every prefetch and the outer query when the planner has resolved the company or year. |
| 4.5 | Use `SearchParams(exact=True)` on full vectors only for evaluation ground truth, never in production. |
| 4.6 | Keep `apply_grounding_policy` and `safe_answer` unchanged: citations must match retrieved chunk IDs, and images that can't be used give `visual_evidence_omitted`. |

### 4.3 Expected speed for top 20 (100 PDFs, 5,880–8,674 visual pages)

| Path | Time |
|---|---|
| Rerank 200 candidates with full vectors | **19 ms** (**measured**, compute only, 2 threads) |
| Exact full scan (no pooling) | 454–729 ms compute (**measured**); ~0.7–1.5 s on Colab (**estimate**) |
| **Recommended flow end to end, warm** | **~0.1–0.25 s** (**estimate**) |
| First query after a restart | + ~0.2–0.5 s disk read (**estimate**) |
| Qdrant reference: 21k pages, cloud, network included | 0.31 s vs 3.75 s exact, 12× (**published**) |

### 4.4 What the LLM receives

| Item | Amount |
|---|---|
| Text + `table_markdown` of the top 5 pages | ~5,000 tokens (~4,000 characters per page, **measured**) |
| Page PNGs | Top 1–2 pages only, for chart or table questions (~1,000 tokens each, **estimate**) |
| Never sent | Vectors; all 20 retrieved pages (~20,000 tokens) |

## 5. Colab runtime

### 5.1 Layout and sizes (100 PDFs; 40% visual, 59% in brackets)

| Location | Contents | Size |
|---|---|---|
| `/content/rag/qdrant/storage/` (local disk) | `visual_pages` full float16 | 1.55 GB (2.29) |
| | pooled rows + columns + HNSW | 0.11 GB (0.17) |
| | `docs_text` + payloads | ~0.15–0.25 GB |
| `/content/rag/pages/` | Page PNGs, 376 KB each (**measured**) | 2.2 GB (3.3) |
| `/content/rag/metadata.sqlite3`, `checkpoints.sqlite` | Signatures, documents, LangGraph state | < 50 MB |
| Drive (persistent) | Snapshots + PNG tar + both SQLite files | **~4–6 GB of 15 GB free** |
| RAM while serving | Pooled vectors + HNSW + page cache for full vectors | ~1.6–2.5 GB of ~12.7 GB |
| GPU | ColPali (~6–7 GB) + optional Qwen3-VL-2B (~4–5 GB) | Fits a 16 GB T4 (**estimate**) |
| GPU time to ingest | 5,880–8,674 visual pages at ~1 page/s | ~1.6–2.4 h (**estimate**) |

### 5.2 Recommendations

1. **Run the Qdrant server binary on the VM.** Embedded local mode is pure Python, slow, and warns above 20k points.
2. **Keep the Qdrant storage on `/content`, never on the Drive mount.** Drive is a network filesystem, slow for memory-mapped random reads, and a disconnect can corrupt it.
3. **Persist with snapshots.** Snapshot each collection and copy it to Drive together with `metadata.sqlite3`, `checkpoints.sqlite` and the PNG tar, every N documents and at session end. Restore all of them together at session start.
4. **Use the batch approach (local PC → Drive → Colab) for ingest.**
   - Upload the next batch while the current one is processing.
   - Delete a batch's PDFs only after its snapshot is safely on Drive.
   - Keep the PNGs, since the vision answers need them.
5. **Warm the page cache after a restore** with about 20 representative queries before serving.
6. **Keep the same root path in every session** (`RAG_LOCAL_DIR=/content/rag`), because image paths are absolute.
7. **Run a single uvicorn worker**, as today. A Qdrant server would allow more workers, but the 4-slot `resilience.Calls` pool and the SQLite checkpointer have a single writer.
8. **Handle a missing T4.** Fall back to text-only retrieval with a warning, don't fail, and skip ColPali query encoding.

## 6. Agents and checkpointing

Full design: [financial_report_agentic_ai_recommendations.md](financial_report_agentic_ai_recommendations.md).

| Flow | Nodes | New nodes | Checkpoint |
|---|---|---|---|
| **A. Report generation** (background job, `POST /reports`) | 15 top-level + a 6-node section subgraph (fan-out, at most 3 at a time) | `report_planner`, `source_resolver`, `profile_builder` (+ approval gate), `narrative_research`, `numeric_consistency_critic`; optional `visual_qa` | `thread_id = report_id`, `durability="sync"`, saved after every node |
| **B. Q&A** (`POST /chat/financial_report_qa` + `conversation_id`) | 10 (existing 8 + `conversation_memory` + `report_facts`) + a `report_handoff` route | `conversation_memory`, `report_facts` | `thread_id = conversation_id`, `durability="async"` |

Recommendations:
1. **Install `langgraph-checkpoint-sqlite`.** Today only `langgraph-checkpoint` 4.3.0 is present. Compile both graphs with a saver; `SqliteSaver.from_conn_string` is a context manager. Use Postgres if there are several users.
2. **Split `generate_financial_report.generate()` into node functions** without changing behaviour. Keep its trace spans, atomic writes and the 17 `Decimal` reconciliations.
3. **Keep large files out of the state.** PDFs, charts, `evidence.json` and `analysis.json` go in as paths + hashes, so a checkpoint is about 0.5–2.5 MB per report.
4. **Retry policy matches `resilience.py`:** automatic retries only on HTTP 429/503. Ambiguous timeouts are rerun from a checkpoint instead. Idempotency key: `report_id:node:section:attempt`.
5. **Refuse to resume when the index has changed:** if the Qdrant/ColPali signature differs from the one saved in the checkpoint.
6. **Version every rerun:** outputs go to `output/pdf/<TICKER>_<YEAR>/<report_id>/v<N+1>/`, so earlier versions stay intact.
7. **Endpoints:** `/reports`, `/reports/{id}`, `/events`, `/review`, `/resume`, `/rerun`, `/checkpoints`.
8. **Use the new corpus in the agents.**
   - `source_resolver` reads `edgar/pdf_manifest.jsonl` (and the AnnualReports manifest for Apple).
   - `profile_builder` drafts a profile for a new company, with mandatory human approval.
   - `numeric_consistency_critic` checks figures against XBRL companyfacts.

## 10. Decision rules from the Colab evaluation

| Decide | Rule |
|---|---|
| Use pooled prefetch + full rerank | Top-20 recall against full exact ≥ 0.90 and NDCG@20 ≥ 0.93 (Qdrant: 0.917 / 0.952), and rerank R@5 within 0.01 of full on chart and table queries |
| Add pooled stages to the text prefetch | The three-way prefetch beats `text_summary` on chart and image queries |
| Prefetch limit | 100 unless 200 improves R@5 by ≥ 0.01 |
| Mean vs max | Mean, unless `max_rows` beats `mean_rows` by > 0.02 on chart queries (not expected: 0.759 vs 0.952 published) |
| Visual threshold | Pick the lowest drawing threshold that keeps chart and table recall while staying near 40% of pages |
| Pooled-only (2,000-document scale only) | `rows_cols` R@5 within 0.03 of full on chart + table queries; otherwise keep full vectors (23–46 GB) or quantize them |

## 14. Risks

| Risk | Mitigation |
|---|---|
| No T4 available on free Colab | Text-only fallback with a warning; queue ingest batches for later |
| float16 NaN on T4 | Stop on non-finite output; rerun in bfloat16 (L4/A100) or float32 |
| Session ends mid-ingest | Snapshot every N documents; idempotent `doc_id` skip; batch approach |
| Drive filling up during snapshot rotation | Delete the old snapshot only after the new one is copied and verified |
| Automatic eval queries favour text search | Hand-written chart and table queries; per-content-type metrics |
| Index changed under a running report | Signature check on resume |
| Third-party PDFs for Apple | Mark the source; EDGAR XBRL as numeric cross-check |
