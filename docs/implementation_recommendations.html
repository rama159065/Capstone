Implementation recommendations: financial-report Q&A domain on Qdrant + ColPali (Colab)

Superseded for 500–1,000 documents: see financial_rag_final_design.md. It adds 10-K HTML/iXBRL as the text and number source (20% of ARS PDF text pages are garbled), a facts DB, number-aware search, PDFs instead of stored PNGs, a serving VM, and costs.

Date: 2026-11-04. Status: recommendations for implementation. Nothing below has been implemented in the RAG or agent code yet. The post-implementation assessment uses section 12.

2.2 Recommendations

  1. Add data/raw/financial_report_qa/edgar/pdfs/ to .gitignore, but commit edgar/pdf_manifest.jsonl. The PDFs are 0.98 GB, and the manifest holds the URL, accession number and SHA-256 for each one, so the PDFs can be downloaded again.
  2. Treat the manifest as the source of record. Ingest from the manifest, not from a folder glob, so ticker, year, source_url, accession_number and content_sha256 reach the Qdrant payload.
  3. Keep the download options as they are: --max-mb 80 and --min-pages 20.
  4. Raise the limit to 120 MB only if WMT FY2024 (115 MB) is needed.
  5. AAPL, XOM, UNH, ORCL and LLY file no ARS, and META's ARS filings contain no PDF. Use AnnualReports.com or rendered 10-K HTML for those companies.
  6. Use XBRL facts as a numeric cross-check, not as the main source.
  7. The numeric_consistency_critic compares report figures with companyfacts values for the same concept and period.
  8. Any mismatch above rounding sends the report to needs_review.
  9. Record each source's licence or terms in the manifest's source_name. EDGAR is the official record; AnnualReports.com is a third-party mirror.

→ metadata.sqlite3 records the document → snapshot every N documents

4.2 Query flow (one query_points call for the visual side)

query → ColPali query vectors (pads removed) + MiniLM text vector
      → prefetch mean_rows (limit 100) ┐
      → prefetch mean_cols (limit 100) ├─► rerank with full colpali MaxSim → top 20 visual pages
      → prefetch summary   (limit 100) ┘
docs_text: dense + bm25 → RRF (k=60) → lexical rerank (as today)
fuse visual + text hits → evidence_guard → top 5 pages → answer_agent
#Recommendation
4.1Replace the single text prefetch in retrieve_visual (limit=max(30, top_k)) with the three prefetches. Today, ColPali only reranks pages the text search already found.
4.2Start with limit 100 per prefetch (≤300 unique candidates). Use 200 only if the Colab evaluation shows higher recall. Qdrant used 200 per shard with 4 shards (published).
4.3Always with_vectors=False. Vectors stay inside Qdrant, and the application handles only IDs, scores and payload.
4.4Apply ticker/year filters inside every prefetch and the outer query when the planner has resolved the company or year.
4.5Use SearchParams(exact=True) on full vectors only for evaluation ground truth, never in production.
4.6Keep apply_grounding_policy and safe_answer unchanged: citations must match retrieved chunk IDs, and images that can't be used give visual_evidence_omitted.

5.2 Recommendations

  1. Run the Qdrant server binary on the VM. Embedded local mode is pure Python, slow, and warns above 20k points.
  2. Keep the Qdrant storage on /content, never on the Drive mount. Drive is a network filesystem, slow for memory-mapped random reads, and a disconnect can corrupt it.
  3. Persist with snapshots. Snapshot each collection and copy it to Drive together with metadata.sqlite3, checkpoints.sqlite and the PNG tar, every N documents and at session end. Restore all of them together at session start.
  4. Use the batch approach (local PC → Drive → Colab) for ingest.
  5. Upload the next batch while the current one is processing.
  6. Delete a batch's PDFs only after its snapshot is safely on Drive.
  7. Keep the PNGs, since the vision answers need them.
  8. Warm the page cache after a restore with about 20 representative queries before serving.
  9. Keep the same root path in every session (RAG_LOCAL_DIR=/content/rag), because image paths are absolute.
  10. Run a single uvicorn worker, as today. A Qdrant server would allow more workers, but the 4-slot resilience.Calls pool and the SQLite checkpointer have a single writer.
  11. Handle a missing T4. Fall back to text-only retrieval with a warning, don't fail, and skip ColPali query encoding.

Full design: financial_report_agentic_ai_recommendations.md.

Recommendations:

  1. Install langgraph-checkpoint-sqlite. Today only langgraph-checkpoint 4.3.0 is present. Compile both graphs with a saver; SqliteSaver.from_conn_string is a context manager. Use Postgres if there are several users.
  2. Split generate_financial_report.generate() into node functions without changing behaviour. Keep its trace spans, atomic writes and the 17 Decimal reconciliations.
  3. Keep large files out of the state. PDFs, charts, evidence.json and analysis.json go in as paths + hashes, so a checkpoint is about 0.5–2.5 MB per report.
  4. Retry policy matches resilience.py: automatic retries only on HTTP 429/503. Ambiguous timeouts are rerun from a checkpoint instead. Idempotency key: report_id:node:section:attempt.
  5. Refuse to resume when the index has changed: if the Qdrant/ColPali signature differs from the one saved in the checkpoint.
  6. Version every rerun: outputs go to output/pdf/<TICKER>_<YEAR>/<report_id>/v<N+1>/, so earlier versions stay intact.
  7. Endpoints: /reports, /reports/{id}, /events, /review, /resume, /rerun, /checkpoints.
  8. Use the new corpus in the agents.
  9. source_resolver reads edgar/pdf_manifest.jsonl (and the AnnualReports manifest for Apple).
  10. profile_builder drafts a profile for a new company, with mandatory human approval.
  11. numeric_consistency_critic checks figures against XBRL companyfacts.
